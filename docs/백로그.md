## v1.5.0 — 토글 신뢰성 (2026-09-09 실사용 발견, 우선순위 1)

### 배경

2026-09-09 수업 중 「켜기를 눌러도 응답이 없다」가 여러 번 발생. 소스 확인 결과 `toggleRecord()`의 구조 문제가 드러났다.

```
toggleRecord() 현재 흐름
① 폴더 확인 → ② 이미 켜짐이면 끄고 종료 → ③ git 저장소 확인
→ ④ guards.confirmRemoteOk()  (확인 창이 한 번 더 뜰 수 있음)
→ ⑤ "켜기/취소" 다이얼로그 → ⑥ setRecording(true)
→ ⑦ recorder.recoverPending()   ★ git add + commit — 느리고 실패 가능
→ ⑧ prepareNotes() → ⑨ treeProvider.refresh()
```

⑦이 수 초~수십 초 걸리는데 **화면에 아무 변화가 없다.** 사용자는 눌리지 않았다고 판단하고 다시 누른다.

### 항목

### 참고 — 확장 잘못이 아닌 부분

같은 날 java 프로세스 127개·CPU 100% 상황에서도 「눌러도 반응 없음」이 있었다. **Extension Host는 단일 스레드**라 다른 확장(Java 언어 서버)이 폭주하면 이 확장의 명령도 큐에서 대기한다. 이건 구조상 어쩔 수 없다 — 다만 **B2(진행 표시)가 있으면 "대기 중"임을 사용자가 알 수 있다.**

### 판정 기준

- B1: 켜기를 5회 연타 → `recoverPending()` 호출 1회만, lock 오류 0
- B2: 켜기 클릭 즉시 진행 표시가 뜨고, 완료 시 사라진다
- B3: `.git/index.lock`을 인위로 만든 상태에서 켜기 → 상태바 ⚠ + 원인 문구, 켜짐으로 오인되지 않음
- B4: 같은 상황에서 git 프로세스가 없으면 자동 회복
