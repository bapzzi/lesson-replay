# 수업 리플레이 2.0 ① 설계: 누구나 쓰는 기록 + 한눈에 읽히는 내보내기

> 상태: 오너 확정(2026-10-02 설계 인터뷰). 이 문서는 "현재 목표 상태"만 담는다. 이력은 git.
> 범위: 2.0 ①단계. ②영어 표시, ③AI 요약은 별도 spec으로 연다.

## 0. 목적과 결정 요약

라이브 코딩 수업(LG CNS 시간표)에 맞춰진 확장을 **마켓 사용자 전반**(부트캠프·강의·독학, 어떤 언어든)이 그대로 쓰고 쉽게 고칠 수 있게 하고, TIL 내보내기를 **맨 위 한 화면만 읽어도 오늘 한 일을 아는** 문서로 바꾼다.

| 결정 | 선택 | 버린 대안과 이유 |
|---|---|---|
| 대상 | 마켓 사용자 전반 | 본인 전용(이미 마켓 배포 중), 부트캠프 한정(독학 배제) |
| 언어 | 표시 언어(한·영) + 프로그래밍 언어 대응 둘 다 | 한쪽만 |
| 하루 단위 | 시간표는 선택, 비우면 자동 세션 | 프리셋만(독학에 어색), 파트 폐지(필기 틀·파트별 배운 것 소실) |
| 기본 시간표 | **기존 7칸 유지**. 자동 세션은 사용자가 비웠을 때만 | 기본값 빈 목록(기존 마켓 사용자 동작이 바뀜) |
| 필기 틀 | 틀 파일 직접 편집 | 틀 여러 개 고르기(매일 고르는 단계), 설정 문자열(여러 줄 편집 불편) |
| 요약 | 기본은 확장이 기록만으로 정리, AI는 선택 기능(③) | AI 전용(모델 확장 필요·결과 매번 다름·코드 외부 전송) |
| 구조 | 구간 계산을 한 함수로(접근 B) | 분기 덧붙이기(접근 A, 분기가 세 곳에 흩어짐) |
| 출시 | 1.5.0 확정 → 2.0 ①②③ 단계별, 단계마다 노트북 실사용 | 한 번에 2.0, 내보내기만 먼저 |
| diff 문법 색칠 | 넣는다(highlight.js) | 빼기(용량·테마 관리 부담. 오너가 넣기로 결정) |

## 1. 하루를 나누는 규칙 (구간)

- `segmentDay(activityTimes, config)` 한 함수가 구간 목록을 정한다(`lib/model.js`). 화면·필기 틀·내보내기·사이드바가 모두 이 결과를 쓴다.
- **시간표 있음**(`lessonReplay.blocks` 비어 있지 않음): 지금과 같다. 파트1~N + 쉬는 시간 + 시간 외. 기본값은 기존 7칸 그대로.
- **시간표 없음**(`blocks: []`): 커밋 시각과 필기 시각을 활동으로 보고, 활동 사이가 `lessonReplay.sessionGapMinutes`(기본 30)분을 넘으면 새 세션. 이름 「세션 1·2·3」, 범위 = 첫 활동~마지막 활동. 시간 외·쉬는 시간 개념 없음.
- 미니맵: 구간 폭 = 구간 길이 비례. 자동 세션 사이 빈 시간은 고정 폭 틈.
- 시간표에 묶인 기능: 「수업 시간인데 기록 꺼짐」 알림은 시간표 있는 사람만. 필기 자동 생성은 시간표 있으면 평일 아침(지금), 없으면 요일 무관하게 그날 첫 기록 켜기·첫 저장 때.
- 기존 사용자 영향: 없음(기본 시간표 유지).

## 2. 필기 틀

- 틀 파일: 필기 폴더의 `_틀.md`(영어 표시면 `_template.md`, 둘 다 있으면 `_틀.md` 우선). 없으면 내장 기본 틀.
  - 내장 기본(시간표 있음): `# {날짜} ({요일}) 수업 필기` + 안내 2줄 + `{파트}` (지금과 같은 결과)
  - 내장 기본(시간표 없음): `# {날짜} ({요일}) 학습 필기` + 빈 본문
- 자리표시: `{날짜}`=`2026-10-05`, `{요일}`=`월`, `{파트}`=시간표 파트 제목 줄들(`## 파트1 (09:10~10:20)`, 시간표 없으면 빈칸). 영어 별칭 `{date}` `{weekday}` `{parts}`.
- 명령 `lessonReplay.editTemplate` 「필기 틀 편집」: 틀 파일이 없으면 내장 기본으로 만들어 연다. 사이드바 「오늘 필기」 항목 옆 버튼.
- 유지: 틀에서 온 줄은 타임라인에 기록하지 않는다(첫 저장 기준선 + 파트 제목 규칙). 시간표 변경 시 파트 시각 현행화는 `{파트}`로 생긴 제목 줄에만.
- 뺀 것: 틀 여러 개·과목별 틀.

## 3. 내보내기 (`복기/<날짜>-복기.md`)

순서와 내용(예시 = 9/15 실측 구조):

1. 제목 `# 2026-09-15 (화) 학습 기록` + 사실 한 줄: 기록 시간 범위 · 구간 수 · 파일 수(새로 n · 수정 n · 삭제 n) · 필기 수 · 갈아엎음 수. 다음 줄 「가장 많이 바뀐 곳: <폴더> (파일 n · +a −d)」(폴더 = 변경 파일을 바로 위 폴더로 묶었을 때 추가+삭제 줄 합이 가장 큰 폴더. 동률이면 파일 수가 많은 쪽).
2. `## 한눈에` 표: 구간 | 시간 | 필기 수 | 주로 만진 파일(변경량 상위 2개 + 「외 n」, 새로 만든 파일·여러 구간은 괄호 표기). 기록 없는 구간은 표에서 빼고 표 아래 「기록 없음: 파트4·6·7」 한 줄.
3. `## 흐름`: 구간별 소제목. 필기(시각 · 본문)와 코드(시간 범위 · 파일명 · 상태 · 구간 수·변경량 · 요약 줄)를 시간순 교차. 같은 파일 연속 구간은 한 줄로 합침(화면 묶음과 같은 규칙). 파트별 「배운 것」이 있으면 소제목 아래.
4. `## 다시 볼 곳`: ★ 표시 씬, 갈아엎은 파일, 하루 4구간 이상 고친 파일(시행착오 후보).
5. `## 부록 A: 파일별 하루 변화`: 파일마다 「그날 첫 커밋 직전 → 마지막 커밋」 diff 하나. 제목에 전체 경로 1회.
6. `## 부록 B: 시행착오 후보의 구간별 변화`: 4번의 파일만 구간별 diff(고친 순서).
- 본문은 파일 이름만, 동명 파일은 상위 폴더를 붙여 구분(칩 규칙과 같음).
- `includeTilPrompt` 옵션 유지(맨 위).
- diff 예산: 부록 A·B 합계 상한 유지(넘으면 생략 개수 표기, 조용한 누락 금지).

## 4. 프로그래밍 언어 대응

- 요약 줄(함수 문맥): 확장에 `media/gitattributes`(확장자 → git 내장 diff 드라이버: python·java·kotlin·golang·rust·cpp·csharp·php·ruby·css·html·markdown)를 넣고, 시그니처 추출 git 명령에만 `-c core.attributesFile=<그 파일>`과 JS·TS용 `-c diff.js.xfuncname=<function·class·화살표 함수 정규식>`을 붙인다. 사용자 저장소에 쓰지 않는다. 저장소 `.gitattributes`가 우선.
- 쓸모없는 줄 거르기(`SIG_NOISE`) 확대: Python `from … import`, `#include`, `using`, `require(`, SQL `--`, `<!--`, `#!`, 닫는 괄호만 있는 줄. Markdown `#` 제목은 거르지 않는다(확장자 판단).
- diff 문법 색칠: highlight.js 브라우저 빌드(공통 언어 묶음, BSD-3, 라이선스 표기)를 웹뷰에 넣는다. 확장자 → 언어 매핑, 모르는 확장자는 색 없음. 색은 VS Code 기본 테마(Dark Modern / Light Modern / 고대비) 값을 CSS로 직접 지정(웹뷰는 현재 테마의 문법 색을 읽을 수 없음). 줄 단위 색칠(여러 줄 주석·문자열 중간 줄 오차 허용).

## 5. 첫 사용 안내와 문구

- 시작 안내(walkthrough) 첫 단계: 「시간표가 있는 수업」(설정의 시간표 열기) / 「자유 학습」(`blocks`를 `[]`로 저장) 선택.
- 문구 일반화: 「수업」이 맞지 않는 곳은 「학습」·「기록」으로. 상태바 `⏺ 수업 기록중` → `⏺ 기록중`, `⊘ 수업 기록 꺼짐` → `⊘ 기록 꺼짐`. 확장 표시 이름은 유지.
- 사용자에게 보이는 문구를 한 곳(`lib/i18n.js` + `package.nls.json`)으로 모은다. 영어 번역은 ②.
- 폴더 이름 `필기/`·`복기/` 기본값 유지. 영어 기본 폴더는 ②에서 새 사용자에게만.

## 7. 검증 기준 (구현 전 지정)

- `npm test` 전부 통과. 추가 테스트: 구간 계산(시간표 / 자동 세션 / 경계 30분), 틀 자리표시 치환, 내보내기 구조(섹션 순서·누락 0), 언어별 요약 줄(Python·SQL·C·JS·Markdown), 확장자 → 하이라이트 언어 매핑.
- 내보내기 측정(9/15 실제 기록, 스크래치 복사본에서만 실행): 「부록」 앞 ≤ 80줄 · 전체 ≤ 827줄(1.5.0의 1,655줄 절반) · 1.5.0 내보내기에 있던 필기 9개·파일 15개 전부 포함.
- 자동 세션 측정: 9/15를 `blocks: []`로 렌더 → 30분 규칙대로 세션이 나뉘는지(기대 세션 수를 커밋·필기 시각으로 미리 계산해 비교).
- 화면: 600·1280·1920px 렌더, 스크립트 오류 0, Impeccable 0건, 글자 크기 3단, 사용자 표면 줄표 0.
- 패키징: `npx @vscode/vsce package` 성공, highlight.js 라이선스 파일 포함.
- 실기(오너, 수업 시간 밖 설치): 자유 학습 모드 1회, 틀 편집 1회, 내보내기 1회.

## 8. 손대지 않는 것

- 기록 방식(git 자동 커밋), 저장소 감시, 토글 신뢰성(1.5.0 그대로).
- 기존 데이터 형식(`필기/<날짜>.md`·`-타임라인.md`·`-복기노트.json`·`-복기마크.json`·`-복기정리.json`). 새 형식 없음, 이관 없음.
